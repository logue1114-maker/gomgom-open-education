# Reading curriculum resources on supported Android versions

The engine curriculum loader used InputStream.readAllBytes(), which is absent on Android API26. A real first install of the global Android candidate crashed before country selection with NoSuchMethodError in GlobalCurriculum.read. The declared minimum API26 remains supported; it is not raised to avoid the defect.

StreamBytes.read uses ordinary InputStream/ByteArrayOutputStream operations available on that platform. It preserves every source byte, handles partial and zero-length bulk reads, propagates IO failures and leaves stream closure to the caller. The same reader is used privately for both language resource loaders. No curriculum data, question, answer or learning record format changes.

Run gradle :math:engine:test --tests '*StreamBytesTest' --tests '*WorldCurriculumTest' --tests '*NamibiaPrimaryTest'. Tests cover UTF8/CRLF across buffers, empty and partial streams, ownership, failures, current curriculum registration and selected Namibia generation. Android app code, SDK configuration, learner records and device evidence are private. Engine checks alone do not prove full Android learning, every device version, or release readiness.

The real Grade1 selector also exposed an unmapped comparison topic merely because the Korean catalog marks it as introductory grade0. A selected national curriculum now governs the private current-grade selector. National diagnostic scope no longer treats every introductory catalog skill as already learned; it uses past mapped grades or explicit learned confirmations. With no previously learned scope, first setup opens learning and the daily card offers practice without inventing an assessment. General practice and explicit confirmations remain available; old records and questions are retained.

The broad engine run also exposed early vector-norm repetition: bounded random attempts could revisit a condition even though unused integer-coordinate triangles remained. The norm path now enumerates the same existing triangle bounds with coordinate swaps/signs and chooses an unseen condition before revisiting the oldest. It does not enlarge numbers, change answers or count presentation IDs as new facts. The existing VectorFoundationPracticeTest independently solves 150 distinct visible conditions per type; rerun it along with the resource/scope tests.
